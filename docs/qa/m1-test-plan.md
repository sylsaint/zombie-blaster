# M1 测试计划（可玩切片：第 1–3 关）

> v0.1，2026-10-09，游戏测试。依据 [`../design/acceptance.md`](../design/acceptance.md) v0.1 和 [`../design/overview.md`](../design/overview.md) 的 M1 范围；任务编号对应 GitHub issue（标签 `M1`）。验收标准编号不改，这里只做映射和判定方法。

## 验证方式

- **GUT**：数值和规则类，PR 必须带对应测试，CI 绿灯才进入人工验证。
- **headless**：`godot --headless` 跑压测场景和关卡，检查报错、单帧耗时、批次数。
- **真机**：每个里程碑一次，低端机（Helio G85 / 骁龙 680，4GB）和中端机（骁龙 7 Gen 1）。
- 每个 PR 的验证结论以 PR 评论给出：通过 / 退回（附 bug issue 链接）。

## 边界和回归用例（acceptance.md 之外补充）

- **ED-01** 一帧内同时被多只杂兵碰到导致人数降到负数：人数夹到 0，只触发一次失败结算。
- **ED-02** 升级三选一弹出期间小队被碰撞或精英死亡：时钟为 0 时不结算伤害，不叠加第二个三选一面板（排队依次弹出）。
- **ED-03** 精英死亡冻结与升级暂停同帧发生：冻结结束后正常进入三选一，时钟不卡在 0。
- **ED-04** 拖动手指移出屏幕再回来、多指同时触摸：小队不跳变、不越界。
- **ED-05** 恰好站在两扇门分界线上：只触发一扇（AC-GT-01 的边界）。
- **ED-06** 人数 149 过乘人门：结果封顶 150，飘字"已满"。
- **ED-11** 连续穿过多扇射速 +15% 门：按 [`../design/squad-and-gates.md`](../design/squad-and-gates.md) 规定叠加（乘法或加法以文档为准），有上限的话不能超过上限；第 3 关的射速门在关卡数据里存在且可触发。
- **ED-12** 同一帧连过两扇武器 +1 门，或已在 M1 最高档时再过武器 +1 门：外观档只按最终武器档切换，不出现枪和衣服档位对不上、闪烁或多一次绘制调用。
- **ED-07** Boss 阶段转换无敌期间的伤害：不扣血、不推进阶段，伤害数字不显示或显示免疫。
- **ED-08** 结算时切后台 / 杀进程：金币和首通标记不重复发放，也不丢失（AC-RW-03/06）。
- **ED-09** 应用切后台再回来：游戏暂停，时钟不跳帧，不触发一大批碰撞。
- **ED-10** 失败后立刻重开：上一局的子弹、敌人、伤害数字全部清空，时钟为 1。

## 缺陷流程

退回的问题开 GitHub issue，标签 `bug` + `M1`，写复现步骤、期望、实际、对应 AC 编号，指派技术负责人，并在原 PR 评论里贴链接。严重程度：阻断（崩溃、无法通关、存档丢失）/ 严重（违反 AC）/ 一般（体验和表现问题）。
